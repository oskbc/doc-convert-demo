## 1. 本書の目的・分掌
本ドキュメントは、システム化の対象範囲、実装すべき機能、および満たすべき性能・品質基準を定義し、発注者と受注者の間で合意形成を図ることを目的とする。

### 1.1. 位置付けと分掌
- **要件定義書（本書）**: 「**何を（What）**」作るかを定義する。業務フローおよび画面・機能の網羅性を担保する。
- **基本設計書**: 要件を「**どのように（How）**」実現するかを定義する。アーキテクチャ、データ構造、I/F仕様等を決定する。
- **詳細設計書**: プログラミング可能なレベルまでロジックや内部構造を詳細化する。

| 対象 | 範囲内（In Scope） | 範囲外（Out of Scope） | 備考 |
| :--- | :--- | :--- | :--- |
| **業務範囲** | 受注管理、出荷管理 | 請求管理、会計連携 | 請求・会計は現行パッケージを使用 |

| **利用ユーザ** | 社内営業部、倉庫担当者 | 代理店、エンドユーザ | |

## 8. 非機能要件
IPA「非機能要求グレード」等の観点に基づき定義する。

| 分類 | 項目 | 要求内容・目標値 | 備考 |
| :--- | :--- | :--- | :--- |
| **可用性** | 稼働時間 | 平日 9:00 - 20:00 | 土日祝および夜間は停止許容 |
| | 目標稼働率 | 99.5% 以上 | 計画停止を除く |
| | RTO/RPO | 目標復旧時間: 4時間以内<br>目標復旧時点: 1日前（日次バックアップ時点） | |
| **性能** | 画面応答 | 通常時 2秒以内、ピーク時 5秒以内 | 検索結果1000件以内において |
| | スループット | 同時アクセス数: 最大100ユーザ | |
| **セキュリティ** | 認証・認可 | 多要素認証（MFA）の実装<br>ロールベースアクセス制御（RBAC） | |
| | 暗号化 | 通信経路: SSL/TLS<br>DB保存: AES-256 | |
| **拡張性** | 将来予測 | 3年後のデータ量倍増に耐えうること | ディスク拡張容易性の確保 |
| **その他** | 多言語対応 | 日本語のみ | 将来的に英語対応の可能性あり |
| | 環境適合 | Google Chrome, Edge 最新版 | IEは非対応 |

## 9. 品質・運用・環境要求
### 9.1. 品質要求
- テスト方針概要、バグ検出率の目標、コードカバレッジ目標など。
- 詳細は「45_テスト計画書」にて定義する。

### 9.2. 運用要求
- バックアップ頻度、世代管理数
- ログ保存期間（アクセスログ: 3年、操作ログ: 1年 等）
- 障害時の連絡体制（詳細は「53_運用・保守計画書」へ）

### 9.3. 開発・本番環境要件
| 環境 | 用途 | 構成概要 | アクセス制限 |
| :--- | :--- | :--- | :--- |
| **開発環境** | 実装・単体テスト用 | AWS t3.medium / RDS db.t3.micro | 開発拠点IPのみ許可 |
| **検証環境** | 結合・総合テスト用 | AWS t3.large / RDS db.t3.small | 開発拠点 + 顧客IP許可 |
| **本番環境** | サービス提供用 | AWS m5.large x 2 (冗長化) / RDS Multi-AZ | インターネット公開 |
