## 1. 本書の目的・分掌
本ドキュメントは、プロジェクト遂行上で発生した課題（未決事項、リスク、トラブル、Q&A）を一元管理し、解決までのプロセスを追跡することを目的とする。

- **管理対象**: プロジェクト進行に影響を与える課題全般（仕様、スケジュール、体制、環境等）
- **運用ルール**: 
    - 週次定例にてステータス棚卸しを実施。
    - 解決（クローズ）した課題は、定期的に別アーカイブへ移動または非表示とする（Markdownの肥大化防止）。
- **関連資料**:
    - 担当者は [33_体制図](../20_ITPJ_Specs/33_体制図.md) に基づく。
    - システム的な詳細Q&Aやバグ一覧として [35_課題一覧](../20_ITPJ_Specs/35_課題一覧.md) が別途存在する場合、重要度「高」のものは本書にも転記し、PM管理下で状況を同期する。

## 2. 定義事項
### 2.1. 優先度（Priority）
| 優先度 | 定義 | 目安 |
| :---: | :--- | :--- |
| **高** | **緊急・ブロッキング** | 直ちに対応が必要。進行がストップする、またはリリース不可となる課題。 |
| **中** | **重要** | 指定期限までの解決が必要。スケジュール遅延の要因となりうる。 |
| **低** | **軽微** | 解決が望ましいが、回避策がある、またはリリース後の対応でも可。 |

### 2.2. ステータス（Status）
| ステータス | 定義 |
| :---: | :--- |
| **新規** | 起票された直後の状態。 |
| **検討中** | 対応方針を検討している、または調査中の状態。 |
| **対応中** | 方針が決定し、作業を実行している状態。 |
| **確認待ち** | 対応が完了し、起票者や顧客の確認・承認待ちの状態。 |
| **保留** | ペンディング。特定の条件が整うまで対応を凍結する状態。 |
| **完了** | 解決済み。再発防止策まで完了していること。 |
