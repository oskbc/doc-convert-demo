## 1. 本書の目的・分掌
本ドキュメントは、基本設計書の方針に基づき、開発（プログラミング）に着手できるレベルまでシステム仕様を詳細化したものである。

### 1.1. 分掌
- **基本設計書**: アーキテクチャ、方式、ルールの策定（方針定義）。
- **詳細設計書（本書）**: クラス、メソッド、パラメータ、設定値レベルの定義（実装定義）。
- **個別仕様書（Catalog）**: 画面レイアウト、ER図など、量的な仕様の定義（`../20_ITPJ_Specs/` 配下に格納）。

本書は全体の目録としての役割を果たし、具体的な仕様値については各リンク先の個別仕様書を参照することを正とする。

### 4.2. エラーハンドリング（共通）
HTTPステータスコードとクライアント側の挙動定義。

| Status | 意味 | クライアント挙動 |
| :--- | :--- | :--- |
| 200 | 成功 | 処理継続 |
| 400 | バリデーションエラー | エラーメッセージを表示 |
| 401 | 未認証 | ログイン画面へ強制遷移 |
| 403 | 権限なし | 「権限がありません」画面を表示 |
| 500 | サーバエラー | 「システムエラーが発生しました」と表示 |

### 5.2. 実行制御詳細
個別のフロー図に記載しきれない詳細設定。
- **ジョブスケジューラ設定**: AWS EventBridge / CRON式 `0 0 * * *` (毎日0時)
- **リトライポリシー**: 
    - 最大リトライ回数: 3回
    - リトライ間隔: 5分 (Exponential Backoff)
- **排他制御**: 処理開始時にDBロックを取得し、多重起動を防止する。

## 6. 機能設計：データ構造
### 6.1. データモデル
- **テーブル一覧**: [30_テーブル一覧](../20_ITPJ_Specs/30_テーブル一覧.md)
- **ER図**: [31_ER図](../20_ITPJ_Specs/31_ER図.md)

### 6.2. データのライフサイクル
- **登録・更新**: 各機能仕様に準ずる。作成日時(`created_at`)、更新日時(`updated_at`)はDBトリガーまたはORMで自動設定。
- **削除**: 原則として**論理削除**（`deleted_at` is not null）を採用。
- **保存期間**: トランザクションデータは5年保持。5年経過後のデータは月次バッチでS3 Glacierへアーカイブし、テーブルから物理削除する。

## 7. 機能設計：ログ・共通処理
### 7.1. ログ設計
アプリケーションが出力すべきログの定義。

| ログレベル | 出力基準 | 出力内容例 |
| :--- | :--- | :--- |
| **ERROR** | 業務継続不可、システム異常 | StackTrace, RequestID, UserID |
| **WARN** | 業務継続可能だが注意が必要 | バリデーションエラー詳細, 外部APIタイムアウト |
| **INFO** | 正常系の主要イベント | ログイン成功, バッチ開始/終了, 決済完了 |
| **DEBUG** | 開発・デバッグ用詳細情報 | SQLクエリ, 入出力パラメータ（個人情報マスク済） |

- **ログフォーマット**: JSON形式（Datadog/CloudWatch Logsでの解析用）
- **ローテーション**: コンテナ標準出力へ吐き出し、AWS基盤側で収集・ローテート管理。

### 7.2. その他共通機能
- **日付処理**: システム内部はUTC、表示時にJSTへ変換。
- **国際化（i18n）**: 文言はリソースファイルで管理（現段階では `ja.json` のみ）。

## 8. 非機能設計詳細
基本設計で定めた方針に対する、具体的な設定値。

### 8.1. 性能・拡張性（Scalability）
- **APサーバ**: CPU使用率 60% 超過でオートスケールアウト（最大10台）。
- **DBサーバ**: コネクションプール最大数 100。
- **タイムアウト設定**:
    - API Gateway: 29秒
    - Load Balancer: 60秒
    - フロントエンドリクエスト: 10秒

### 8.2. セキュリティ詳細
- **パスワードポリシー**: 8文字以上、英大文字・小文字・数字・記号を含むこと。
- **セッション管理**: Token有効期限 1時間、Refresh Token有効期限 30日。
- **WAF設定**: SQLインジェクション、XSSパターンのブロックルール適用。
