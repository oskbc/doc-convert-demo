## 2. 発生原因
### 2.1. 直接原因
データベース(RDS)のCPU使用率が100%に張り付き、応答不能となったため。

### 2.2. 根本原因
14:00に実行された「在庫一括更新バッチ」において、検索条件のインデックスが効いていないSQLが含まれており、大量のフルスキャンが発生してDB負荷が急増した。
当該バッチは昨日リリースされた機能であり、開発環境（データ量小）では検知できなかった。

## 4. 再発防止策
### 4.1. 暫定対応（即時）
- 問題のSQLをチューニングし、インデックスを追加した修正パッチを適用済み（同日 20:00）。
- 該当バッチの実行時間を、業務時間外（22:00）に変更した。

### 4.2. 恒久対応（中長期）
- **SQLレビューの強化**: `EXPLAIN` 実行計画の確認をリリース判定の必須項目に追加する。
- **テストデータの見直し**: 開発・検証環境においても、本番相当のデータ量を投入してパフォーマンステストを実施する運用に変更する。
