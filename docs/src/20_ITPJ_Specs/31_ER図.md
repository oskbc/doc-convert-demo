## 1. ER図
Mermaid記法による論理ER図。

```mermaid
erDiagram
    %% マスタ系
    users {
        bigint id PK
        string email UK
        string password_hash
        string name
        string role "admin/user"
    }

    customers {
        bigint id PK
        string code UK
        string company_name
        string phone
        string address
    }

    products {
        bigint id PK
        string code UK
        string name
        int price
        int stock_quantity
    }

    %% トランザクション系
    estimates {
        bigint id PK
        string estimate_no UK
        bigint customer_id FK
        date valid_until
        int total_amount
        string status "draft/approved"
        timestamp created_at
    }

    estimate_items {
        bigint id PK
        bigint estimate_id FK
        bigint product_id FK
        int quantity
        int unit_price
    }

    orders {
        bigint id PK
        string order_no UK
        bigint customer_id FK
        bigint estimate_id FK
        timestamp order_date
        string payment_status
    }

    %% リレーション定義
    customers ||--o{ estimates : "1人の顧客は複数の見積を持つ"
    customers ||--o{ orders : "1人の顧客は複数の注文を持つ"
    
    estimates ||--|{ estimate_items : "見積は複数の明細を持つ"
    products  ||--o{ estimate_items : "商品は複数の明細に含まれる"
    
    estimates ||--o| orders : "見積から注文が生成される(0 or 1)"
    
    users ||--o{ estimates : "ユーザ(営業)が見積を作成する"
```

## 2. 特記事項

  - **論理削除**: 全てのエンティティは物理削除せず、`is_deleted` フラグにて管理する。
  - **外部キー制約**: DBレベルでFK制約を付与し、不整合（Orphan Record）を防ぐ。
  - **インデックス**: `email`, `code`, `order_no` 等の検索キーおよび外部キーカラムにはIndexを作成する。
