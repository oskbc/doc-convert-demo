## 1. 概要
主要なユースケースにおける画面遷移の流れと、そのトリガーとなるアクション（ボタン押下等）を定義する。

## 2. 画面遷移詳細

### 2.1. 見積作成〜承認フロー
SCR-101(一覧) から始まり、登録・承認を行うまでの遷移。

```mermaid
stateDiagram-v2
    [*] --> SCR_101_一覧

    state SCR_101_一覧 {
        [*] --> 検索
        検索 --> リスト表示
    }

    SCR_101_一覧 --> SCR_102_登録 : [新規作成]ボタン
    SCR_101_一覧 --> SCR_103_詳細 : [詳細]リンク

    state SCR_102_登録 {
        入力 --> 確認モーダル : [保存]ボタン
        確認モーダル --> バリデーションエラー : 入力不備
        確認モーダル --> SCR_103_詳細 : 保存成功
    }

    state SCR_103_詳細 {
        閲覧 --> SCR_102_編集 : [編集]ボタン
        閲覧 --> 承認モーダル : [承認依頼]ボタン(営業)
        閲覧 --> 承認完了 : [承認]ボタン(Mg)
        閲覧 --> 差戻し完了 : [差戻し]ボタン(Mg)
    }

    SCR_103_詳細 --> SCR_101_一覧 : [戻る]ボタン
```

### 2.2. 共通エラーフロー

例外発生時の遷移ルール。

```mermaid
graph LR
    Any[任意の画面] -->|セッション切れ| Login[SCR-001 ログイン]
    Any -->|権限エラー(403)| Error403[エラー画面(権限なし)]
    Any -->|システムエラー(500)| Error500[エラー画面(システム障害)]
    
    Login -->|再ログイン| Any
```

## 3\. モーダル・ポップアップ定義

画面遷移を伴わない（URLが変わらない）サブ画面の定義。

| ID | 親画面 | 名称 | 用途 |
