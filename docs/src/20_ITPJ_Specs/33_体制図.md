## 1. 体制図（Reporting Line）

```mermaid
graph TD
    %% 顧客側
    subgraph Client [発注者: {{ClientName}}]
        Owner[プロジェクトオーナー]
        ClientPM[顧客PM / 窓口]
        User[現場担当者]
        
        Owner --- ClientPM
        ClientPM --- User
    end

    %% 弊社側
    subgraph Vendor [受注者: {{MyCompanyName}}]
        PM[PM: プロジェクトマネージャー]
        PL[PL: リーダー/アーキテクト]
        
        subgraph DevTeam [開発チーム]
            SE1[SE: フロントエンド]
            SE2[SE: バックエンド]
            PG[PG: 実装担当]
        end
        
        subgraph InfraTeam [インフラチーム]
            Infra[インフラエンジニア]
        end
    end

    %% コミュニケーションライン
    ClientPM <==>|定例会/課題管理| PM
    PM --- PL
    PL --- DevTeam
    PL --- InfraTeam
```

## 2. 役割・責任範囲

| ロール | 担当者 | 役割・責任 |
| :--- | :--- | :--- |
| **PM** | 佐藤 | プロジェクト全体の進捗・予算・課題管理。顧客との折衝窓口。 |
| **PL** | 鈴木 | 技術選定、アーキテクチャ設計、コードレビュー、開発チームの技術指導。 |
| **SE/PG** | 田中、高橋 | 詳細設計、実装、単体テスト、結合テスト。 |
| **Infra** | 伊藤 | AWS環境構築、CI/CDパイプライン整備、監視設定。 |

## 3. 会議体設定

| 会議名 | 頻度 | 参加者 | 目的 |
| :--- | :--- | :--- | :--- |
| **定例進捗報告会** | 週1回 (月曜) | 顧客PM, PM, PL | 進捗報告、課題共有、仕様Q\&A |
| **朝会** | 毎日 (09:30) | Vendor全員 | タスク確認、ブロッカーの共有 |
| **仕様レビュー会** | 随時 | PM, PL, SE | 設計書の品質チェック |
