## 1. 凡例
* 対象業務フロー: **見積～受注プロセス**
* 区分: TO-BE (新業務フロー)

## 2. フロー図

```mermaid
graph TD
    subgraph Sales ["営業担当"]
        Start(("開始")) --> A["顧客ヒアリング"]
        A --> B["システムで見積作成"]
        D["見積書発行・送付"] --> E{"顧客承認"}
        E -- 失注 --> End(("終了"))
        E -- 受注 --> F["注文書受領"]
        F --> G["受注登録"]
    end

    subgraph System ["新システム"]
        B --> C{"値引率チェック"}
        C -- 規定内 --> D
        C -- 規定外 --> H["承認ワークフロー発動"]
        I["承認完了通知"] --> D
        G --> J["受注データ保存"]
    end

    subgraph Manager ["承認者(課長)"]
        H --> K{"承認判断"}
        K -- 否認 --> B
        K --承認 --> I
    end
```

## 3. 各ステップの詳細補足

| ステップID | 業務名 | システム機能ID | 補足事項 |
|:---|:---|:---|:---|
| B | 見積作成 | SCR-005 | 過去の見積を流用コピー可能とすること |
| H/K | 承認フロー | SCR-008 | 承認依頼はメールおよびSlackで通知すること |
