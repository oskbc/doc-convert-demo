## 2. フロー詳細

### 2.1. [Flow-01] 見積〜受注プロセス
見積作成から、承認を経て受注確定するまでのフロー。

```mermaid
graph TD
    %% 定義: アクターごとのレーン
    subgraph Sales [営業担当]
        Start((開始))
        InputEstimate[見積情報入力]
        RequestApprove[承認依頼]
        CheckReject[差戻し確認]
        ConfirmOrder[受注確定操作]
    end

    subgraph Manager [マネージャー]
        CheckEstimate[見積内容確認]
        Judge{承認判定}
        Approve[承認処理]
        Reject[差戻し処理]
    end

    subgraph System [新システム]
        SaveDraft[一時保存]
        NotifyMgr[承認依頼通知]
        UpdateStatus_App[ステータス更新:承認済]
        NotifySales[承認完了通知]
        NotifyReject[差戻し通知]
        CreateOrder[受注データ作成]
        End((完了))
    end

    %% フロー接続
    Start --> InputEstimate
    InputEstimate --> SaveDraft
    SaveDraft --> RequestApprove
    RequestApprove --> NotifyMgr
    NotifyMgr --> CheckEstimate
    CheckEstimate --> Judge
    
    Judge -- OK --> Approve
    Approve --> UpdateStatus_App
    UpdateStatus_App --> NotifySales
    NotifySales --> ConfirmOrder
    ConfirmOrder --> CreateOrder
    CreateOrder --> End

    Judge -- NG --> Reject
    Reject --> NotifyReject
    NotifyReject --> CheckReject
    CheckReject --> InputEstimate
```

### 2.2. [Flow-02] 在庫引当プロセス

受注確定時にシステム内部で行われる自動処理フロー。

```mermaid
graph TD
    subgraph Order [受注処理]
        Start((開始))
        OrderIn[受注確定]
    end

    subgraph System [在庫管理ロジック]
        CheckStock{在庫数確認}
        Reserve["引当処理<br>(引当数+1, 有効数-1)"]
        ErrorStock[在庫不足エラー]
    end

    subgraph DB [データベース]
        ReadStock[(在庫参照)]
        UpdateStock[(在庫更新)]
    end

    Start --> OrderIn
    OrderIn --> CheckStock
    CheckStock -.-> ReadStock
    
    CheckStock -- 在庫あり --> Reserve
    Reserve --> UpdateStock
    UpdateStock --> End((完了))

    CheckStock -- 在庫なし --> ErrorStock
    ErrorStock --> End
```

## 3\. 補足事項・例外処理

  - **承認時の金額閾値**: 見積金額が100万円未満の場合は、マネージャー承認をスキップし自動承認とする（詳細はロジック定義参照）。
  - **在庫不足時**: 画面上で「在庫不足」アラートを表示し、受注確定をブロックする。バックオーダー（取り寄せ）対応はPhase2にて検討。
