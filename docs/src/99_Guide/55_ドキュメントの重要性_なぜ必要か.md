# 55. ドキュメントの重要性 / なぜ必要か

## 1. ドキュメント作成の目的
「動くコードがあればドキュメントはいらない」というのは誤解です。
私たちは以下の3つの目的のためにドキュメントを作成します。

### 1.1. 未来の自分とチームのため（記憶の外部化）
人間の記憶は曖昧です。3ヶ月前の自分がなぜその設計にしたのか、コードだけでは読み取れない「意図」や「経緯」を残すことで、**保守コストを劇的に下げます**。

### 1.2. コミュニケーションコストの削減
同じ説明を何度も口頭で行うのは非効率です。ドキュメントがあれば「ここを読んでおいて」の一言で済み、**認識の齟齬（言った言わない）を防ぐ**ことができます。

### 1.3. 品質の担保と証明
頭の中だけで考えたロジックには穴があります。文字や図に書き出すプロセスそのものが、思考の整理となり、**バグの未然防止**に繋がります。また、顧客に対して「正しく設計した」という証明（エビデンス）になります。

## 2. 良いドキュメントの条件
| 条件 | 説明 | NG例 |
| :--- | :--- | :--- |
| **最新であること** | 実装と乖離したドキュメントは「嘘」であり、ない方がマシです。 | コードを直したが設計書は直していない。 |
| **検索性が高いこと** | どこに何があるかすぐに分かる構造であること。 | ファイル名が「資料1.pdf」「最新.xlsx」になっている。 |
| **読み手が明確** | 誰に何を伝えたいかが意識されていること。 | 顧客向け資料に専門用語（変数名など）を羅列する。 |

## 3. ドキュメントレベルの考え方
全ての資料を完璧に作る必要はありません。目的に応じて「深さ」を調整します。

- **Level 1 (メモ)**: 自分の思考整理用。体裁は問わない。
- **Level 2 (チーム共有)**: チームメンバーが理解できる。Markdown推奨。
- **Level 3 (公式資料)**: 顧客提出用、または長期保存用。表記揺れや体裁も整える。

> **心構え**
> ドキュメントは「納品物のオマケ」ではなく、**「ソフトウェアの一部」**です。
